# ADR-0004: 取り込みジョブに Cloud Run jobs を採用

## 状態
確定

## 決定
Cloud Run jobs（バッチ、プル型）。手動起動を基本とし、必要なら Cloud Scheduler で定期化。

## 根拠
リアルタイム性不要で、複数ファイルをまとめて処理したい。「起動したらフォルダをスキャンして未処理を処理する」プル型が運用イメージに合う。

## 却下した代替案
- Cloud Run functions（イベント駆動）→ ファイル到着で自動起動。リアルタイム性が要らないので過剰。
- Cloud Composer（Airflow）→ 単一・低頻度ジョブには明確にオーバースペック。
- Dataform → SQL 主体でテキストパースには不向き。
- ローカル実行 → 運用最小だが、自動化余地を残すため job を採用。
- コスト: jobs と functions はどちらも実行時間課金・アイドル無料。本規模では差は事実上ない。選定軸はコストではなくトリガー方式。
